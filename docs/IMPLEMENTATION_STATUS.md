# Implementation Status

LocalView is being implemented as a sequence of independently verifiable vertical slices against the expanded product specification. The repository deliberately separates compile/contracts from runtime proof: a capability is not marked complete merely because an adapter or model exists.

## Landed architecture

- Rust workspace with protocol, discovery, sessions, observation, security and authenticated loopback control plane.
- Semantic/state diff, layout, visual, responsive, source and token-budget layers.
- Capture planning, engine escalation, network, console, accessibility, performance, flow, design grammar and artifacts.
- CLI and MCP bridge.
- Tauri 2 desktop dashboard, system tray, standalone localhost preview windows and a feature-gated native child-WebView workspace.
- In-page instrumentation and a bounded native bridge for observer events and deterministic queued page actions.
- Managed WebViews emit bounded semantic/geometry packets and support synchronous snapshot/inspect flows.
- The control plane exposes a narrow authenticated fresh semantic-snapshot gate. Each request enqueues a new snapshot action for the exact session, waits only for the matching action result, projects the result into the bounded `PageSnapshot` contract and rejects stale, unrelated or malformed results.
- A pure Rust progressive target resolver binds one stable `ElementRef` to an ordered `element → component → section → viewport` plan. Element geometry is exact-ref based and bounded; component targets require corroborated explicit `source.component` ownership on an ancestor; section targets require an explicit semantic section/landmark ancestor; viewport remains an explicit caller-selectable fallback rather than a silent widening policy.
- Native viewport capture adapters exist for Windows WebView2, macOS WKWebView and Linux WebKitGTK behind an isolated platform boundary.
- Bounded native CSS-region execution is connected above those adapters: the coordinator acquires the real managed viewport, requires exact restore, applies private redaction, verifies live viewport consistency, crops a bounded CSS target in Rust and registers region-scoped Visual evidence without adding separate platform-specific region screenshot APIs.
- Desktop `capture_progressive_target` connects the fresh semantic snapshot and deterministic resolver to that same audited native transaction. Resolution happens inside the per-session capture gate, the requested target level must exist exactly, snapshot viewport must match the caller viewport, live route/viewport drift after acquisition fails closed, and the final receipt preserves target provenance, confidence and snapshot version/route alongside the visual evidence receipt.
- Baseline-driven changed-region scheduling is connected to the same native transaction. Each scheduling pass settles/freezes/acquires/restores/redacts the managed viewport exactly once, decodes the redacted frame once, compares it with a compatible bounded in-memory baseline, and selects unchanged, bounded regions or viewport fallback deterministically. Multiple changed regions are cropped from the same decoded redacted frame rather than recapturing or redecoding for each region.
- A deterministic `localview-token-budget` visual packet planner ranks changed-region and progressive `element → component → section → viewport` evidence by bounded information-gain × confidence × relevance / normalized-cost utility, suppresses highly redundant nested regions, respects an explicit image-region budget and fails closed on invalid geometry/scores. Selection is model/provider agnostic and does not require cloud inference.
- Desktop `capture_visual_packet` connects that planner to the live runtime. With a positive image budget it takes the existing per-session gate, resolves an optional stable ref from one fresh semantic snapshot, executes exactly one shared settle → freeze → native viewport acquisition → restore → private-redaction transaction, computes changed-region candidates from the already-redacted frame, selects evidence, crops/persists only the selected redacted regions and advances the private baseline only after selected evidence succeeds. An image-region budget of zero returns explicit metadata-only output before native acquisition.
- `localview-token-budget` now also carries the exact four-dimensional V3 Perception Budget Contract: `latency_ms`, `text_tokens`, `image_regions` and `chromium_spawns`. The evaluator deterministically reports all exceeded dimensions, fails closed if any dimension is exceeded without an allowed escalation reason, and records one of the explicit reasons `critical_issue`, `explicit_deep_mode`, `insufficient_evidence` or `browser_specific_suspicion` when an over-budget operation is admitted.
- `capture_visual_packet` consumes that full contract rather than only a text/image sub-budget. It records measured pre-persistence latency, the bounded packet text-token estimate, selected image-region count and `chromium_spawns = 0` for the native WebView path, then evaluates the budget before selected visual artifacts are persisted or the private changed-region baseline is advanced. The resulting `PerceptionBudgetDecision` is returned beside the packet rather than included inside its token-counted payload, avoiding circular accounting.
- CPU/RAM are intentionally not modeled as Perception Budget dimensions. They remain part of the separate Runtime Resource Governor together with capture storage, browser-process count, hidden surfaces, analysis concurrency and cache limits.
- Changed-region baselines are private-redacted `Arc<RgbaImage>` frames in a deterministic 96 MiB / 32-entry LRU cache. Compatibility is bound to route, CSS viewport, device scale factor and native pixel dimensions. Incompatible contexts are invalidated, oversized frames are not cached, and a baseline advances only after all selected evidence emissions succeed.
- Bounded local visual artifact persistence and daemon Visual evidence metadata registration are connected to the desktop capture path.
- Cross-platform CI covers the Rust core on Ubuntu, macOS and Windows plus the Linux Tauri/frontend compiler and desktop contract gates.
- Dedicated GUI smoke gates prove real rendered pixels for Windows/WebView2, macOS/WKWebView and Linux/WebKitGTK through production-shared snapshot helpers. Windows creates a real Win32 parent window, initializes an STA COM WebView2 environment/controller, navigates to a deterministic loopback HTTP fixture with exact URI/navigation correlation, verifies live DOM/CSS/geometry, captures through production-shared `CapturePreview`, fully decodes the PNG and checks the known rendered center pixel. Linux runs a real GTK/WebKitGTK surface under Xvfb; macOS owns the real AppKit main thread, creates NSApplication + NSWindow + WKWebView, pumps NSRunLoop and verifies the same deterministic rendered-pixel contract after native snapshot/PNG decode.

## Native workspace safety gate

Tauri capability selectors are scoped by **WebView label** instead of parent window. `main` receives only the dashboard capability; `preview-*` and `workspace-*` receive only the loopback preview bridge capability. The `native-workspace` Cargo feature is the only path that enables `tauri/unstable`, and CI checks both default and native-workspace builds.

Compiling native child WebViews still does **not** make them the default workspace. `WorkspaceSurfaceSupport.default_mode` remains `iframe` until overlay/chrome composition, focus/input routing, DPI/bounds behavior, resize/minimize/restore, crash/reconnect cleanup and navigation policy are verified on Windows WebView2, macOS WKWebView and Linux/WebKitGTK.

## Stable visual capture transaction

The current visual-capture slice wires a fail-closed private-region transaction around native pixel acquisition:

1. Validate the viewport and optional bounded CSS region, then preflight the exact session-owned managed surface.
2. Acquire a bounded **per-session** capture gate so independent sessions do not serialize globally.
3. For progressive semantic capture, request one newly completed authenticated semantic snapshot while holding that gate; resolve the exact stable ref into evidence-backed target levels and reject caller/snapshot viewport mismatch before native acquisition.
4. Wait for the authenticated stable-capture settle gate.
5. Ask the managed page to freeze visual motion through a private `freeze_visuals` bridge action carrying only bounded private selectors.
6. Resolve those selectors inside the managed page to bounded viewport-relative rectangles and counts. Selector strings, DOM text, attributes and arbitrary page payload do not cross back in the freeze acknowledgement.
7. Acquire native **viewport** pixels through the platform adapter. Explicit regions, progressive semantic targets, changed-region scheduling and visual-packet selection intentionally reuse this auditable platform path instead of creating independent region backends.
8. Restore visual state with the exact freeze token, even when native acquisition fails.
9. Verify the captured frame against the live CSS viewport reported by the freeze receipt. Progressive/visual-packet capture additionally binds the live frame route and viewport to the fresh semantic snapshot when a stable ref is supplied; route/viewport drift fails closed after restoration and before any artifact write.
10. Revalidate the bounded mask geometry and redact the captured viewport PNG **in memory** using `localview-visual`.
11. For an explicit or progressive region target, crop the already-redacted viewport PNG using bounded CSS-to-native scaling, then decode the result again to verify the produced pixel dimensions.
12. For changed-region scheduling or a visual packet, decode the redacted viewport once, resolve a compatible route/viewport/scale/pixel baseline, run the bounded tile/coalescing planner, and choose `unchanged`, bounded `regions`, or `viewport` fallback. The first compatible-frame miss produces a viewport candidate; an unchanged pass produces no changed-region candidate.
13. For `capture_visual_packet`, combine that changed-region plan with any evidence-backed progressive targets, rank them deterministically under the image-region budget, suppress redundant nested evidence, and serialize the compact metadata packet under the text-token budget.
14. Measure the current visual-packet usage as elapsed pre-persistence latency, serialized packet token estimate, selected image-region count and zero Chromium spawns on the native path. Evaluate all four Perception Budget dimensions before artifact persistence. An overrun without an allowed reason fails closed; an allowed overrun records the exact escalation reason in the returned decision.
15. Only after budget admission, crop/persist the selected evidence from the same already-redacted decoded frame. The private baseline is committed only after the complete selected evidence emission succeeds; evidence failure or budget rejection leaves the prior baseline authoritative.
16. `image_regions = 0` remains a metadata-only path: it evaluates the full Perception Budget but short-circuits before managed-surface preflight, the per-session capture gate and native pixel acquisition.
17. Persist processed frames and register viewport or dedicated `/evidence/visual-region` metadata only after restore acknowledgement, target/live-state validation, complete private-mask application and Perception Budget admission succeed.

The page-side freeze pauses bounded Web Animations when available and applies temporary CSS suppression for animation/transition motion. Every freeze has an 8-second fail-safe lease that attempts automatic restoration if the coordinator disappears. Private geometry resolution is bounded to 16 selectors, 4,096 unique matched elements and 256 visible rectangles inside a maximum 100,000 × 100,000 CSS-pixel viewport. Invalid selectors, malformed/non-finite geometry, budget overflow, malformed PNG data, frame-dimension mismatch, live viewport drift, route drift in progressive capture, restore failure, incomplete mask application or invalid region geometry fail closed and prevent uncertain pixels from being persisted.

The final redaction/crop boundary is native PNG processing in Rust, not a CSS overlay. `localview-visual` decodes bounded PNG input, verifies decoded dimensions against native capture metadata, validates geometry before mutation, scales CSS coordinates to native pixels, clips within bounded image memory, fills private pixels opaquely, crops requested regions only after redaction and re-encodes within bounded memory/encoded-size limits. Changed-region and visual-packet scheduling reuse the decoded `RgbaImage` directly for all selected crops so one scheduling transaction does not multiply PNG decode or native acquisition cost by region count.

Internal `freeze_visuals` / `restore_visuals` actions are not exposed through the generic public action-enqueue route. Private selectors travel only in the internal capture envelope. Freeze tokens remain control-flow state and are not emitted in final capture receipts or Visual evidence metadata. Region evidence uses a separate authenticated endpoint whose schema requires `target = "region"`, a positive in-viewport CSS rectangle, nonzero pixel dimensions, a content-addressed artifact ID, an approved native backend and a loopback HTTP(S) route. Progressive receipts expose only bounded semantic provenance/target metadata plus the underlying visual evidence receipt; they do not expose raw snapshot payloads or private selectors. Changed-region baselines hold only already-redacted pixels in bounded process memory and are never exposed as public evidence or persisted as a separate raw baseline store.

## Verification state

The fresh-snapshot/progressive-resolver/settle/freeze/private-geometry/restore/redaction/region-crop/changed-region/visual-packet transaction is covered by cross-platform Rust compile/test gates and the Linux Tauri/frontend contract suite. The progressive contracts verify exact newly completed snapshot use, exact-level selection with no silent component/section widening, snapshot/caller viewport binding, one shared native acquisition, live route/viewport drift rejection, provenance retention and the existing restore → private redaction → crop → persistence order. Adversarial resolver coverage includes missing refs, NaN/infinite/zero/offscreen geometry, invalid viewport, mismatched component ownership and duplicate component/section rectangles.

The visual-packet policy contracts verify local high-information evidence wins over an expensive viewport fallback, `image_regions` caps distinct evidence, redundant nested context is suppressed, zero image budget is metadata-only, invalid/out-of-viewport geometry fails closed and equal candidate sets produce input-order-independent selection. Desktop authority contracts additionally require exactly one shared native acquisition, fresh semantic resolution before acquisition, changed-region planning before selection, restore/redaction authority reuse, selection before persistence, baseline commit after selected evidence succeeds, and true-viewport fallback cost rather than a synthetic tiny rectangle.

The Perception Budget core contracts cover all four specification dimensions, deterministic multi-dimension overrun reporting, fail-closed rejection without an escalation reason, serialization of the four allowed reason values, admitted explicit deep-mode overruns and zero-budget behavior. Desktop authority contracts require the full budget evaluation on both metadata-only and image paths; for the positive-image path the contract must be evaluated after deterministic packet selection but before selected evidence persistence and before private-baseline commit. The receipt retains the resulting budget decision and the measured usage while the native path records `chromium_spawns = 0`.

The existing visual contracts additionally verify private/public action isolation, bounded selector transport, geometry-only freeze acknowledgements, restore-after-native-failure, restore-before-live-target validation, validation-before-redaction, redaction-before-crop, crop-before-persistence, one shared native acquisition per changed scheduling transaction, baseline compatibility and bounded LRU behavior, direct multi-region cropping from one decoded redacted frame, commit-after-evidence ordering, bounded PNG processing, region-evidence schema isolation and fail-closed malformed geometry/dimension/target handling.

Linux/WebKitGTK has hosted **rendered-pixel proof**: a dedicated Ubuntu GUI smoke job starts a real GTK window and WebKitGTK WebView under Xvfb, loads deterministic localhost HTML, invokes the production-shared visible-snapshot helper, fully decodes the returned PNG and verifies that the center pixel belongs to the known rendered proof region. A missing display, load failure, snapshot failure, invalid/trivial PNG or wrong rendered pixel fails the job.

macOS/WKWebView has equivalent hosted **rendered-pixel proof**. A custom `harness = false` test owns the actual macOS main thread, initializes AppKit, creates a real NSWindow + WKWebView, loads the same deterministic loopback fixture, pumps NSRunLoop until the page is ready, invokes the same WKWebView snapshot helper used by the Tauri adapter, fully decodes the produced PNG and verifies the known center proof pixel. The real GUI test exposed and fixed a production bug where WKWebView's returned NSImage representations were not directly PNG-encodable by ImageIO; production now materializes the snapshot through `NSImage.TIFFRepresentation → NSBitmapImageRep → PNG` before frame validation.

Windows/WebView2 has the matching hosted **rendered-pixel proof**. A custom Windows GUI smoke creates a real Win32 parent window and installed WebView2 controller on an STA COM thread, serves a deterministic fixture from `127.0.0.1`, correlates the exact fixture URI and NavigationId, requires successful navigation, verifies `document.readyState`, route, computed proof color, viewport and proof geometry, then invokes the production-shared `ICoreWebView2::CapturePreview` path. The returned PNG is bounded, fully decoded and required to contain the known red proof region at its center. The harness also tolerates bounded zero-byte speculative/preconnect TCP connections from WebView2 while retaining a hard deadline, per-connection read bounds and full request traces; the rendered-pixel/navigation assertions themselves are unchanged.

The viewport **Native screenshot adapter is Implemented**: all three production platform backends have live rendered-pixel acquisition evidence in dedicated hosted GUI gates, in addition to compile/contracts coverage. **Bounded CSS-region execution, evidence-backed progressive semantic targeting, baseline-driven changed-region scheduling, token-aware progressive visual-packet selection and the first live exact four-dimensional Perception Budget gate are now present** above that acquisition path. `capture_visual_packet` can accept an optional stable ref plus `latency_ms`, `text_tokens`, `image_regions`, `chromium_spawns` and an optional allowed escalation reason; LocalView reuses the single audited private capture authority, admits or rejects the packet before selected visual side effects, and returns the budget decision with the processed evidence metadata.

This does **not** make the entire V3 Active Perception/diagnose-fix budget system complete. The current latency check is measured at the pre-persistence visual-packet admission point rather than a whole-cycle reservation/deadline, and budget authority is not yet generalized across planner stages or Tier-3 engine escalation. CPU/RAM are not missing Perception Budget fields; they belong to the separate Runtime Resource Governor, whose live enforcement is still incomplete. Framework-specific ownership depth, guarded full-page stitching and the complete capture → diff → deterministic verification loop also remain Partial.

## Next vertical slices

The strongest remaining capture/perception gates are:

1. generalize `PerceptionBudgetContract` from the live visual-packet gate into diagnose/fix-cycle planner admission, whole-cycle latency reservation/deadline semantics and Tier-3 engine escalation so escalation reasons are planner-authorized rather than merely caller-supplied;
2. wire the separate Runtime Resource Governor into live CPU/RAM/capture-storage/browser-process/hidden-surface/analysis-concurrency/cache enforcement;
3. true network in-flight accounting plus framework-specific live HMR signals;
4. capture → visual region diff → deterministic verification as one end-to-end loop;
5. deeper source/runtime ownership correlation (sourcemaps plus React/Vue/Svelte adapters) and interactive point-and-select inspector wiring;
6. guarded full-page stitching and responsive/contact-sheet execution;
7. native workspace composition/focus/DPI/crash safety gates before promoting the child WebView surface from feature-gated to default.

The repository should not claim the complete V1/V2/V3 specification is implemented until these live adapters and later verification phases are end-to-end, not merely represented by crates or data models.
