# LocalView v0.2.0-rc.1

> **Unsigned pre-release candidate.** This is the first distributable checkpoint after bounded V1 software-production closure.

LocalView v0.2.0-rc.1 packages the production-closed bounded V1 runtime for Windows, macOS and Linux together with per-platform artifact manifests, SPDX SBOMs and provenance.

## Highlights

### Runtime truth for localhost applications

LocalView discovers and tracks local applications, retains durable project/session identity and combines semantic, visual, network, console, performance, accessibility and source-oriented evidence into a bounded runtime model for both humans and coding agents.

### Evidence-first visual verification

The release includes native rendered-pixel capture paths for:

- Windows / WebView2
- macOS / WKWebView
- Linux / WebKitGTK

Visual evidence is bounded, private-region redaction happens before persistence, and guarded full-page capture is constrained by geometry, memory and absolute-deadline policies.

### Bounded consequential agent actions

Managed WebView interaction supports `click`, `focus`, `type_text`, `key` and `scroll`.

Consequential actions use:

`fresh semantic cut → plan → one-shot confirm → exact dispatch → durable journal → fresh post-dispatch observation → postcondition receipt`.

CLI and MCP expose `plan → confirm → status`; legacy one-step mutation shortcuts remain closed.

### Trusted Fix + Wave 9 bounded verification

The production path carries human-reviewed changes through exact revision/candidate identity, source-only preflight, proven repository-side-effect containment, fresh post-Apply observation, a fixed hard-contract catalog, safe synthetic mutation challenges and actual-vs-predicted impact accounting.

The bounded receipt can verify the exact selected target on the current canonical route. It is intentionally separate from the whole-impact autonomous verdict.

### Production evidence

The bounded V1 software closure includes:

- exact-head cross-platform CI;
- Windows/macOS/Linux release-candidate bundles;
- clean-machine install + first launch;
- rendered-pixel validation;
- release artifact digests;
- SPDX 2.3 SBOM;
- provenance bound to candidate SHA and dependency lockfiles;
- initial-release rollback-state policy;
- machine-enforced production closure with adversarial negative proofs.

## Important release boundary

This candidate is **not a signed final public-production release**.

The following remain external publication requirements:

- **Windows code signing** credentials and signed-installer verification;
- **macOS Developer ID** signing and notarization;
- **production updater-signing authority** for automatic download/install;
- physical W10 mixed-DPI evidence if that topology is advertised as supported.

The current V1 updater is check-only. A pinned HTTPS update channel may report availability, but LocalView does not automatically install an update without production signature-verification authority.

## Whole-impact verification boundary

Bounded target/current-route verification is part of V1.

Whole-application Autonomous Verified is not claimed when the dependency denominator or complete revalidation universe is unknown. Unknown evidence remains unknown.

## Artifacts

The GitHub release workflow builds the release candidate independently on Windows, macOS and Linux. Each platform archive contains:

- the Tauri bundle output;
- `artifact-manifest.json`;
- `sbom.spdx.json`;
- `provenance.json`.

All release evidence is regenerated and verified from the exact release commit before publication.
